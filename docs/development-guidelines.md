# GBA模拟器开发规范指南

本文档旨在为GBA模拟器项目提供统一的开发规范，确保代码质量和团队协作效率。

## 1. 测试规范

### 1.1 测试框架
项目使用 **Jest** 作为主要测试框架，这是当前项目流程中已集成使用的测试框架。

### 12. 测试文件组织
- 所有测试文件统一放置在项目根目录下的 `test` 文件夹中
- 测试文件命名遵循 `*.test.js` 规范
- 测试文件结构应与源代码结构保持对应关系

### 1.3 测试用例要求
测试用例需覆盖以下核心功能模块：
- CPU指令执行
- 内存管理
- 图形渲染
- 输入处理
- 音频处理
- 存档系统

### 1.4 测试命令
```bash
# 运行所有测试
pnpm test

# 运行特定测试文件
pnpm test -- test/filename.test.js

# 运行测试并生成覆盖率报告
pnpm test -- --coverage
```

### 1.5 测试最佳实践
- 每个测试用例应具有明确的描述信息
- 测试用例应保持独立性，避免相互依赖
- 对于复杂功能模块，应包含边界条件测试
- 测试数据应尽量使用真实数据或合理模拟数据

## 2. 依赖管理规范

### 2.1 包管理器
项目统一使用 **pnpm** 作为包管理器，禁止混用npm、yarn等其他包管理工具。

### 2.2 依赖安装
```bash
# 安装生产环境依赖
pnpm add package-name

# 安装开发环境依赖
pnpm add -D package-name

# 安装所有依赖
pnpm install
```

### 2.3 依赖更新
```bash
# 更新特定依赖
pnpm update package-name

# 更新所有依赖
pnpm update
```

### 2.4 依赖删除
```bash
# 删除依赖
pnpm remove package-name
```

### 2.5 文件维护
- 确保 `package.json` 和 `pnpm-lock.yaml` 文件同步维护
- 提交代码时应包含 `pnpm-lock.yaml` 文件
- 避免手动修改 `pnpm-lock.yaml` 文件

## 3. 代码规范

### 3.1 代码风格
- 使用4个空格作为缩进
- 使用单引号而非双引号
- 不使用尾随逗号
- 遵循项目现有的代码风格

### 3.2 命名规范
- 类名使用PascalCase（大驼峰命名法）
- 函数名和变量名使用camelCase（小驼峰命名法）
- 常量名使用UPPER_CASE（全大写加下划线）
- 文件名使用kebab-case（小写加连字符）

### 3.3 注释规范
- 函数应包含JSDoc注释说明
- 复杂逻辑应添加行内注释
- 类和重要模块应包含文件头注释

## 4. Git工作流

### 4.1 分支管理
- 主分支为 `main`，用于发布稳定版本
- 功能开发应在 `feature/*` 分支进行
- 修复bug应在 `bugfix/*` 分支进行

### 4.2 提交信息规范
- 提交信息应使用中文
- 提交信息应简洁明了，说明变更内容
- 使用约定式提交格式（Conventional Commits）

### 4.3 代码审查
- 所有代码变更需通过Pull Request进行
- PR需至少一名团队成员审查通过后方可合并
- PR描述应包含变更内容和测试情况

## 5. 项目特定规范

### 5.1 浏览器API替代
由于项目需要改造为Node.js环境运行，需注意替换原项目依赖的浏览器API：
- 使用终端字符或图像文件替代Canvas渲染
- 使用Node.js文件系统API替代FileReader

### 5.2 Node.js环境适配
- 确保代码兼容Node.js v12+版本
- 使用ES Modules或CommonJS模块系统
- 避免使用浏览器特定API
