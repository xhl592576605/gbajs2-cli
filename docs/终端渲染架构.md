# 终端游戏渲染架构

本文梳理 gbajs2-cli 的画面渲染链路、数据结构与机制，便于后续优化。

---

## 1. 数据流向总览

```
           ┌────────────────────────┐
           │ GameBoyAdvance PPU     │
           └───────────┬────────────┘
                       │ RGBA 帧缓冲 (240×160×4)
                       ▼
        ┌──────────────────────────┐
        │ GameCore → renderWorker  │
        └──────────┬───────────────┘
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│ renderWorker.js                                        │
│ 1. PixelMapper.mapFrame → FrameSurface(rows + meta)    │
│ 2. diffRows(lastFrameRows) → changedRows               │
└──────────┬───────────────────────────────┬──────────────┘
           │                               │
           │ frame-result (frame+diff)     │ returnBuffer
           ▼                               ▼
 ┌──────────────────────────────┐   ┌──────────────────┐
 │ GameCore.emit('frame')       │   │ buffer 池回收     │
 └──────────┬───────────────────┘   └──────────────────┘
            │ frame payload: { frame, changedRows, fps… }
            ▼
 ┌──────────────────────────────┐
 │ React App → TerminalViewport │
 └──────────┬───────────────────┘
            │ direct mode 渲染 (stdout)
            ▼
 ┌────────────────────────────────────────────┐
 │ 终端备用屏幕（diff 写行、隐藏光标）        │
 └────────────────────────────────────────────┘
```

## 2. 模块职责

| 模块 | 位置 | 作用 |
| --- | --- | --- |
| GameCore | `src/game/GameCore.js` | 启动 GBA 核心、控制 Worker、收集 FPS/内存，并把帧事件送给 UI |
| renderWorker | `src/renderers/terminal/renderWorker.js` | 将 RGBA 像素映射成 FrameSurface，并计算行级 diff |
| PixelMapper | `src/renderers/terminal/pixelMapper.js` | 高精度 balanced + TrueColor 字符映射，输出 `rows` |
| TerminalViewport | `src/renderers/terminal/TerminalViewport.js` | 进入 direct mode，对 diff 结果进行 ANSI 写入，负责 resize 清屏 |
| Renderer 导出 | `src/renderers/terminal/index.js` | 统一导出 PixelMapper/TerminalViewport，并提供 Worker URL 工具 |
| CLI 入口 | `src/index.js` | 检查 stdout 是否 TTY，非交互式终端直接退出，确保只存在 direct mode |

## 3. 数据结构

### FrameSurface

```ts
type FrameSurface = {
  rows: string[];      // 含 ANSI 颜色码的文本行
  columns: number;
  rowCount: number;
  width: number;       // 240
  height: number;      // 160
  scaleX: number;
  scaleY: number;
  density: 'balanced';
  theme: 'dark' | 'light';
};
```

### frame 事件 payload

```ts
{
  frame: FrameSurface | null,
  changedRows: number[] | null,
  fps: number,
  duration: number,
  timestamp: number,
  romName: string
}
```

## 4. 渲染管线细节

### 4.1 GameCore → Worker

1. 计算缩放：`App` 调 `buildScaleState()`，若启用 auto-fit 则根据 `process.stdout.columns/rows` 计算 `scaleX/scaleY` 并通过 `GameCore.updateRenderOptions` 通知 Worker。
2. 每帧：GBA 核心生成 RGBA 缓冲 → GameCore 将像素和 `bufferId` 发送给渲染 Worker。
3. Worker 成功映射后返回 `frame-result`；若 diff 判定 `unchanged === true`，只回传 `changedRows`（可能为空）。

### 4.2 PixelMapper 映射

| 模式 | 描述 |
| --- | --- |
| Balanced（默认） | 一个字符映射上下两块像素，使用 `▀` 字符 + 不同前/背景色，兼顾色彩与垂直精度 |
| Block | 每字符显示单色块（`█/░` 等），适合低密度渲染或追求像素感 |
| Braille | 2×4 子像素映射到 Unicode Braille 点阵，可获得更高分辨率效果 |

额外特性：
- 对每个采样块计算平均 RGB，并根据终端主题应用明暗曲线（暗主题稍增亮度，亮主题降低对比度）。
- 输出 ANSI 256 色（`38;5;`/`48;5;`），后续可扩展到 TrueColor。
- 支持主线程 fallback：Worker 出错时 GameCore 会创建 `PixelMapper` 在主线程执行同样的逻辑。

### 4.3 Worker diff 策略

```js
const diffRows = (rows) => {
  if (!lastFrameRows) {
    return { changedRows: rows.map((_, i) => i), unchanged: false };
  }
  const changed = [];
  for (let i = 0; i < max; i += 1) {
    if (rows[i] !== lastFrameRows[i]) {
      changed.push(i);
    }
  }
  lastFrameRows = rows.slice();
  return { changedRows: changed, unchanged: changed.length === 0 };
};
```

- 只比较文本行内容，当色值或字符差异时才标记为 changed。
- 传输时携带 `returnBuffer`，GameCore 收到后释放 buffer 回池，减少 GC。

### 4.4 TerminalViewport direct mode

1. **初始化**：使用 Ink `useStdout()` 获取 stdout，确认 `isTTY` 切换到备用屏幕，隐藏光标并清空。
2. **监听 resize**：注册 `stdout.on('resize')`；触发时清空终端，重置 `prevLinesRef`，下一帧强制全量 diff，避免残影。
3. **渲染**：
   - 拼接 `headerLine`（ROM 名、scale、density、theme）。
   - 如果 `frame.rows` 为空则显示“等待帧数据...”，否则直接插入。
   - 追加状态栏：FPS、Frame duration、CPU%、MEM、Skip、音频状态、控制提示、auto-fit 信息/错误提示。
   - 调用 `computeChangedLineIndexes(prevLines, lines, hintedRows)`，将 Worker 提供的帧行 diff（加 frame offset）与 header/status 的 diff 合并。
   - 对每个变动行执行 `\u001b[${row};1H`、`\u001b[2K`、`write(line)`。
   - 将光标移动到末尾 `\u001b[${lines.length + 1};1H`。

4. **清理**：组件卸载时恢复光标显示、清空屏幕并退出备用屏幕，保证终端状态回到正常模式。

## 5. 渲染机制示意

### 5.1 Balanced 模式像素块

```
GBA 像素 (scaleX=3, scaleY=3)
┌───────┐
│top  █ │ ← 平均 RGB → 前景色
│bottom█│ ← 平均 RGB → 背景色
└───────┘
↓ 映射为
  \u001b[38;5;<fg>m\u001b[48;5;<bg>m▀
```

### 5.2 Braille 模式子像素

```
单字符 2×4 子像素 → Braille 位图
┌────┐     bits → Unicode 0x2800 + bits
│o o │
│ oo │
│  o │
│oo  │
└────┘
```

### 5.3 行级 diff 流程

```
FrameSurface.rows (N 行)
        │
        ▼
Worker diffRows → changedRows [1,4,5,...]
        │             ▲
        │             │ frameOffset + header/status diff
        ▼             │
TerminalViewport.computeChangedLineIndexes
        │
        ▼
逐行 cursorTo + eraseLine + 写入
```

## 6. 终端限制与行为

- CLI 启动时如果 `stdout` 不是 TTY 或缺少 `write`，立即提示“请在支持 ANSI 的终端运行”并退出，避免 fallback。
- 终端 resize 会同时触发：
  1. `TerminalViewport` 清空画布并重置 diff 缓存；
  2. 如果用户开启 auto-fit，`App` 会重新计算 `scaleX/scaleY` 并调用 `GameCore.updateRenderOptions`，Worker 将重新生成 FrameSurface 尺寸。

## 7. 可以着力的优化方向

1. **像素映射性能**：`PixelMapper.sampleAverage/sampleRegion` 是热点，可尝试使用 TypedArray 缓冲或 WebAssembly/SIMD。
2. **颜色表现**：目前使用 ANSI 256 色，可在支持的终端上输出 TrueColor（`38;2;r;g;b`）提升细腻度。
3. **输出对齐**：TerminalViewport 现在左对齐，可根据 `stdout.columns` 计算左右 padding，实现画面与状态栏的居中展示（结合 `string-width`）。
4. **更细粒度 diff**：除了行级 diff，还可以记录行内分段变化，减少 `stdout.write` 的字符数量。
5. **打包/传输**：检查 Worker 的 buffer 池复用情况，避免频繁分配大数组；必要时把 diff 数据进一步压缩。
