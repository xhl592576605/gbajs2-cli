# GBA.js2 Game Boy Advance 模拟器架构分析文档

## 1. 项目整体架构概述

GBA.js2 是一个完全用 JavaScript 编写的 Game Boy Advance 模拟器，采用模块化设计，实现了对 GBA 硬件的完整模拟。项目架构采用分层设计，各模块职责清晰，相互协作组成完整的模拟器系统。

### 1.1 核心架构层次

```
┌─────────────────────────────────────────────────────────┐
│                    用户界面层 (HTML/CSS)                   │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              Canvas 渲染层 (240×160)              │   │
│  └─────────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────┤
│                    模拟器核心层                          │
│  ┌──────────────┐  ┌─────────────┐  ┌─────────────┐   │
│  │   GameBoy   │  │    ARMCore   │  │    MMU      │   │
```

## 2. 各模块详细分析

### 2.1 主模拟器类 (GameBoyAdvance - gba.js)

**职责**：作为整个模拟器的核心控制器，负责协调所有子系统的工作。

**核心功能**：
- **模块初始化与连接**：在构造函数中创建并连接所有子系统（CPU、MMU、IRQ、IO、Audio、Video等）
- **ROM管理**：加载和管理 Game Boy Advance ROM 文件
- **BIOS管理**：加载和管理系统BIOS
- **存档管理**：处理游戏存档的读取、存储和管理
- **运行控制**：提供暂停、重置、步进等运行控制功能
- **画布设置**：管理Canvas渲染目标，支持缩放和适配

**关键数据结构**：
```javascript
this.cpu = new ARMCore();           // CPU核心
this.mmu = new GameBoyAdvanceMMU();    // 内存管理
this.irq = new GameBoyAdvanceInterruptHandler(); // 中断处理
this.io = new GameBoyAdvanceIO();       // I/O寄存器
this.audio = new GameBoyAdvanceAudio();   // 音频系统
this.video = new GameBoyAdvanceVideo();   // 视频渲染
```

**关键方法**：
- `setCanvas(canvas)` - 设置渲染目标
- `setRom(rom)` - 加载ROM文件
- `reset()` - 重置模拟器状态
- `runStable()` - 开始稳定运行
- `advanceFrame()` - 执行一帧
- `pause()` - 暂停模拟器

### 2.2 CPU核心 (ARMCore - core.js)

**职责**：实现 ARM7TDMI 处理器的完整功能，包括 ARM 和 Thumb 两种指令集。

**核心功能**：
- **指令执行**：动态编译和执行 ARM/Thumb 指令
- **寄存器管理**：16个通用寄存器 + 银接寄存器
- **处理器状态**：CPSR、SPSR 等状态寄存器管理
- **模式切换**：支持 7 种处理器模式
- **中断处理**：硬件中断响应和处理

**关键数据结构**：
```javascript
this.gprs = new Int32Array(16);        // 通用寄存器
this.bankedRegisters = [/* 6 个银行 */]; // 链接寄存器
this.cpsrI/F/V/C/Z/N = false;        // 状态标志
this.instructionWidth = 4;               // 当前指令宽度
```

**处理器模式**：
- MODE_USER (0x10) - 用户模式
- MODE_FIQ (0x11) - 快速中断模式
- MODE_IRQ (0x12) - 中断模式
- MODE_SUPERVISOR (0x13) - 管理模式
- MODE_ABORT (0x17) - 中止模式
- MODE_UNDEFINED (0x1b) - 未定义模式
- MODE_SYSTEM (0x1f) - 系统模式

**指令执行流程**：
1. 取指阶段：从内存加载指令
2. 译码阶段：动态编译生成执行函数
3. 执行阶段：调用生成的函数执行指令
4. 写回阶段：更新寄存器和状态标志

### 2.3 内存管理单元 (MMU - mmu.js)

**职责**：管理 GBA 的完整内存映射和访问控制。

**内存区域映射**：
- **0x00000000-0x00003FFF**：BIOS 区域 (16KB)
- **0x02000000-0x020FFFFF**：工作 RAM WRAM (256KB)
- **0x03000000-0x030FFFFF**：内部 RAM IRAM (32KB)
- **0x04000000-0x040003FF**：I/O 寄存器区域 (1KB)
- **0x05000000-0x0503FFFF**：调色板 RAM PRAM (1KB)
- **0x06000000-0x06017FFF**：视频 RAM VRAM (96KB)
- **0x07000000-0x070003FF**：对象属性内存 OAM (1KB)
- **0x08000000-0xFFFFFFFF**：卡带 ROM 区域

**关键类**：
- `MemoryView` - 基础内存视图类
- `MemoryBlock` - 可缓存的内存块
- `ROMView` - ROM 内存视图（只读，支持GPIO）
- `BIOSView` - BIOS 内存视图（只读）
- `BadMemory` - 非法内存访问处理

**关键功能**：
- **内存访问控制**：8/16/32位读写操作
- **等待状态管理**：不同内存区域的访问延迟
- **DMA 控制**：4个 DMA 控制器的管理
- **页面缓存**：指令缓存优化

### 2.4 I/O 系统 (GameBoyAdvanceIO - io.js)

**职责**：实现所有 GBA I/O 寄存器的读写操作。

**寄存器分类**：
- **视频寄存器**：DISPCNT、BGxCNT、BGxHOFS/VOFS 等
- **音频寄存器**：SOUNDxCNT、WAVE_RAM、FIFO 等
- **DMA 寄存器**：DMAxSAD/DAD/CNT 等
- **定时器寄存器**：TMxCNT_LO/HI
- **中断寄存器**：IE、IF、IME
- **串行通信寄存器**：SIOCNT、SIODATA 等

**关键特性**：
- **寄存器映射**：将硬件寄存器映射到内存空间
- **位字段处理**：正确处理寄存器的位字段
- **写时序**：确保寄存器写入的时序正确性

### 2.5 音频系统 (GameBoyAdvanceAudio - audio.js)

**职责**：实现 GBA 的完整音频系统，包括 PSG 和 FIFO 音频。

**音频通道**：
- **方波通道 1&2**：频率、包络、扫频控制
- **波形通道 3**：波形样本播放
- **噪音通道 4**：伪随机噪声生成
- **FIFO 通道 A&B**：DMA 驱动的 PCM 音频

**关键功能**：
- **实时采样**：16kHz 采样率的实时音频生成
- **混合与输出**：多通道音频混合和 Web Audio API 输出
- **音量控制**：主音量和左右声道平衡

**音频处理流程**：
1. 定时器触发音频更新
2. 各通道生成音频样本
3. 应用音量和效果处理
4. 混合所有通道输出
5. 通过 Web Audio API 播放

### 2.6 视频渲染系统 (GameBoyAdvanceVideo - video.js)

**职责**：管理视频渲染管线，包括多种显示模式的支持。

**显示模式**：
- **模式 0**：文本模式，4 层背景
- **模式 1**：混合模式，2 层背景 + 1 层旋转缩放
- **模式 2**：旋转缩放模式，2 层旋转缩放背景
- **模式 3**：位图模式，16000 色
- **模式 4**：位图模式，256 色
- **模式 5**：位图模式，16000 色（小尺寸）

**渲染管线组件**：
- `GameBoyAdvanceSoftwareRenderer`：软件渲染器
- `GameBoyAdvanceRenderProxy`：代理渲染器（支持 Web Worker）
- `GameBoyAdvancePalette`：调色板管理
- `GameBoyAdvanceVRAM`：视频内存管理
- `GameBoyAdvanceOAM`：对象属性内存管理

**渲染流程**：
1. HBlank 开始，更新扫描线计数
2. 渲染背景层（根据模式）
3. 渲染精灵对象
4. 应用窗口效果和混合
5. 输出到 Canvas

### 2.7 中断系统 (GameBoyAdvanceInterruptHandler - irq.js)

**职责**：处理所有类型的中断和定时器。

**中断类型**：
- **VBlank/Hblank/VCOUNT**：视频相关中断
- **Timer0-3**：4 个硬件定时器中断
- **DMA0-3**：4 个 DMA 通道中断
- **串行通信**：SIO 中断
- **按键**：按键输入中断
- **Game Pak**：卡带相关中断

**SWI 处理**：
- **软件中断**：实现完整的 BIOS SWI 功能
- **系统调用**：内存操作、数学运算、压缩解压等

**中断处理流程**：
1. 中断源检测
2. 中断使能检查
3. 中断优先级判断
4. 上下文保存
5. 中断服务程序执行
6. 上下文恢复

### 2.8 指令集实现

#### ARM 指令集 (arm.js)
- **数据处理指令**：ADD、SUB、AND、ORR、EOR 等
- **乘法指令**：MUL、MLA、UMULL、SMULL 等
- **加载/存储指令**：LDR、STR、LDM、STM 等
- **分支指令**：B、BL、BX 等
- **系统指令**：SWI、MRS、MSR 等

#### Thumb 指令集 (thumb.js)
- **精简指令集**：16 位指令编码
- **高密度代码**：更好的代码密度
- **性能优化**：适合移动设备的指令集

### 2.9 外设模拟

#### 按键输入 (keypad.js)
- **键盘映射**：键盘按键到 GBA 按键的映射
- **手柄支持**：HTML5 Gamepad API
- **按键状态管理**：实时按键状态检测

#### 串行通信 (sio.js)
- **多玩家模式**：最多 4 台 GBA 连接
- **传输模式**：8位、32位、UART 等
- **时钟控制**：波特率设置

#### 存档管理 (savedata.js)
- **SRAM**：电池备份 SRAM
- **Flash**：Flash 存储器（512KB/1MB）
- **EEPROM**：串行 EEPROM

#### GPIO (gpio.js)
- **RTC 芯片**：实时时钟芯片模拟
- **通用 I/O**：通用输入输出端口

## 3. 关键数据结构和处理流程

### 3.1 内存访问流程

```
CPU 访问 → MMU → 地址解码 → 区域选择 → 具体访问
                                    ↓
                            等待状态计算 → 周期计数器更新
```

**详细步骤**：
1. CPU 发出内存访问请求
2. MMU 根据地址确定内存区域
3. 检查访问权限和对齐
4. 计算等待状态
5. 执行实际的内存读写
6. 更新周期计数器

### 3.2 指令执行流程

```
取指 → 指令解码 → 操作数获取 → 执行 → 结果写回
  ↓       ↓         ↓        ↓      ↓
缓存检查 → 动态编译 → 寄存器访问 → ALU操作 → 状态更新
```

**详细步骤**：
1. 从 PC 指向的地址获取指令
2. 检查指令缓存，如未命中则编译
3. 解码指令获取操作数
4. 执行指令操作
5. 更新寄存器和状态标志
6. 处理中断和异常

### 3.3 视频渲染流程

```
HBlank 开始 → 扫描线渲染 → 对象渲染 → 混合处理 → 帧布输出
    ↓           ↓          ↓        ↓        ↓
时序更新 → 背景层处理 → 精灵处理 → 特效处理 → 显示完成
```

**详细步骤**：
1. HBlank 期间更新内部状态
2. 逐条扫描线渲染背景
3. 渲染精灵对象（按优先级）
4. 应用窗口和特效
5. 混合所有图层
6. 输出到显示缓冲区

### 3.4 音频处理流程

```
定时器触发 → 通道更新 → 样本生成 → 混合处理 → 音频输出
    ↓           ↓          ↓        ↓        ↓
频率计算 → 包络更新 → 噪音合成 → 音量控制 → WebAudio
```

**详细步骤**：
1. 定时器触发音频更新
2. 更新各音频通道状态
3. 生成音频样本数据
4. 混合所有通道
5. 应用音量控制
6. 输出到 Web Audio API

## 4. 程序启动和运行机制

### 4.1 启动流程

1. **初始化阶段**
   - 创建 GameBoyAdvance 实例
   - 加载 BIOS 数据
   - 设置渲染目标 Canvas
   - 初始化所有子系统

2. **ROM 加载**
   - 文件读取和验证
   - ROM 头部分析
   - 存档类型检测
   - 内存映射设置

3. **系统重置**
   - CPU 复位到初始状态
   - 内存区域清零
   - 寄存器初始化
   - 中断系统使能

**启动代码示例**：
```javascript
// 创建模拟器实例
var gba = new GameBoyAdvance();

// 设置渲染目标
gba.setCanvas(canvas);

// 加载 BIOS
gba.setBios(biosBin);

// 加载 ROM
gba.loadRomFromFile(romFile, function(success) {
    if (success) {
        gba.runStable(); // 开始运行
    }
});
```

### 4.2 运行循环

```
主循环：
  while (!paused) {
    advanceFrame();  // 执行一帧
    if (seenFrame) {
      waitFrame();   // 等待垂直同步
    }
  }

advanceFrame：
  while (doStep()) {
    cpu.step();       // 执行 CPU 指令
  }

  saveDataFlush();      // 处理存档写入
  vblankCallback();     // 垂直同步回调
```

**时序控制**：
- 每帧约执行 280896 个 CPU 周期
- 垂直同步频率约 59.73 Hz
- 使用 setTimeout 控制帧率

### 4.3 帧同步机制

- **VBlank 中断**：标志一帧渲染完成
- **帧率控制**：通过 setTimeout 实现
- **音频同步**：音频缓冲区与视频同步
